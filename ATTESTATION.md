# Attestation & assurance

This release ships with a signed, offline-verifiable security attestation
produced by [`assure`](https://github.com/) (Ed25519 DSSE / in-toto). The
attestation binds the assurance result to this repository's git commit so a
third party can verify, with no network and no account, that these controls
held on this code at this time.

## Files

| File | What it is |
| --- | --- |
| `.assure/report.md` / `.assure/report.json` | Human- and machine-readable assurance report (controls, grade, findings). |
| `.assure/attestation.dsse.json` | DSSE envelope wrapping an in-toto Statement; predicate = the assurance summary + SHA-256 of the report, over the git commit. |
| `attestation/iaiso-release.pub` | Ed25519 **public** key for verification. The private key is never distributed. |

> `.assure/` is a build artifact (git-ignored) and is regenerated by
> `assure scan`. It is included in the release archive so the signed evidence
> travels with the code.

## Verify it yourself

```bash
pip install assure
assure verify --attestation .assure/attestation.dsse.json \
              --pubkey attestation/iaiso-release.pub \
              --report .assure/report.json \
              --root .
```

Verification checks three things independently: the Ed25519 signature over the
DSSE envelope, the SHA-256 of the report matching the attested digest, and the
git commit/file digests of the artifact. Tampering with the report after
signing is caught as a hash mismatch; the wrong key fails the signature.

## Scope — what was attested

The attestation covers the **installable, claim-backed code**: the `core/`
SDKs (Python + eight ports) and the project root. The `vision/` zone is
design/reference material (reference integrations, templates, system sketches)
and is shipped as-is; it is **excluded from the security scan scope** and is
not part of this attestation. This mirrors the two-zone model described in the
READMEs: `core/` is real and tested; `vision/` is design intent.

## Honest notes (the point of a fail-closed attestation)

- **Secrets — pass.** `gitleaks` initially flagged 74 "secrets". All were
  cross-language **conformance test vectors** (`spec/consent/vectors.json`) and
  unit-test fixtures, signed with a fixed, published HS256 conformance key that
  every port must reproduce byte-for-byte and that each file documents as
  "NEVER use in production." They are allowlisted in `.gitleaks.toml` with that
  rationale — a documented false-positive suppression, not a hidden secret.
- **Two scanners were air-gapped in the build environment.** `trivy` and
  `grype` need to download vulnerability/OCI databases, which the build
  sandbox's egress does not allow. They are recorded as **skipped (air-gapped)**
  rather than counted as a false "clean" — run them in networked CI
  (`assure scan`, no `--skip`) to evaluate the IaC/image controls. `govulncheck`
  is likewise not installed here.
- **A vision-zone transitive advisory exists.** `vision/requirements.txt` pulls
  `chromadb` (transitively, via `crewai`) which carries upstream advisories with
  no fixed release available. This is reference-design dependency surface, not a
  dependency of the installable SDK (whose only runtime deps — `pyjwt[crypto]`,
  `pydantic` — are clean). See the header in that file.

## Reproduce

```bash
pip install assure
./tools/install-scanners.sh          # pinned, checksum-verified scanners
assure scan                          # networked CI: evaluates every control
assure scan --skip trivy,grype       # air-gapped: as attested here
```
